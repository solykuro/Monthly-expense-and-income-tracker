# data-backup Specification

## Purpose
以 JSON 檔案匯出與匯入所有項目與設定。因為資料只存在本機，這是換裝置或資料遺失時唯一的還原方式；匯入為完全取代，並在寫入前完成驗證。

## Requirements

### Requirement: 匯出備份

系統 SHALL 在設定頁提供「匯出備份」，產生並下載一個 JSON 檔案，內容包含：`app`（固定為 `fixed-cashflow-planner`）、`schemaVersion`（目前為 1）、`exportedAt`（ISO 8601 時間）、`settings`（初始預留金與推演年數）、`items`（所有收支項目及其金額異動紀錄）。檔名 SHALL 為 `fixed-cashflow-YYYYMMDD.json`，日期為匯出當天。

#### Scenario: 匯出資料

- **WHEN** 使用者在 2026-09-17 點選「匯出備份」，目前有 3 個項目
- **THEN** 系統下載 `fixed-cashflow-20260917.json`，檔案中的 `items` 有 3 筆，且包含所有欄位與異動紀錄

#### Scenario: 沒有項目時匯出

- **WHEN** 使用者在沒有任何項目時點選「匯出備份」
- **THEN** 系統仍下載檔案，`items` 為空陣列，`settings` 為目前設定

### Requirement: 匯入備份（完全取代）

系統 SHALL 在設定頁提供「匯入備份」，讓使用者選擇 JSON 檔案。檔案驗證通過後，系統 MUST 顯示確認對話框，說明匯入會完全取代目前所有項目與設定，並建議先匯出備份；使用者確認後，系統 SHALL 在單一交易中刪除現有資料並寫入檔案內容。

#### Scenario: 確認匯入

- **WHEN** 使用者選擇有效的備份檔並在確認對話框中選擇確認
- **THEN** 目前的項目與設定被檔案內容完全取代，並顯示「已匯入 N 個項目」

#### Scenario: 取消匯入

- **WHEN** 使用者選擇有效的備份檔，但在確認對話框中選擇取消
- **THEN** 目前的項目與設定保持不變

#### Scenario: 確認對話框顯示摘要

- **WHEN** 使用者選擇的備份檔包含 5 個項目，匯出時間為 2026-09-01
- **THEN** 確認對話框顯示「備份檔包含 5 個項目（匯出於 2026-09-01）」，並提醒目前資料會被取代

### Requirement: 匯入驗證

系統 MUST 在顯示確認對話框之前驗證備份檔；任何驗證失敗時，系統 SHALL 顯示錯誤訊息，且 MUST NOT 修改現有資料。驗證內容包含：檔案為有效 JSON、`app` 值正確、`schemaVersion` 為系統支援的版本、`settings` 與每個項目都符合與表單相同的欄位驗證規則。

#### Scenario: 非 JSON 檔案

- **WHEN** 使用者選擇的檔案內容不是有效的 JSON
- **THEN** 系統顯示「檔案格式錯誤，無法讀取」，現有資料不變

#### Scenario: 不是本工具的備份

- **WHEN** 檔案是有效 JSON，但 `app` 不是 `fixed-cashflow-planner`
- **THEN** 系統顯示「這不是本工具的備份檔」，現有資料不變

#### Scenario: 不支援的版本

- **WHEN** 檔案的 `schemaVersion` 大於系統支援的版本
- **THEN** 系統顯示「備份檔版本較新，請更新 App 後再匯入」，現有資料不變

#### Scenario: 項目資料不合法

- **WHEN** 檔案中第 2 個項目的金額為 -100
- **THEN** 系統顯示「第 2 個項目資料有誤：金額必須是大於 0 的整數」，現有資料不變

#### Scenario: 寫入過程失敗

- **WHEN** 使用者確認匯入後，寫入資料庫時發生錯誤
- **THEN** 交易被取消，現有資料保持匯入前的狀態，並顯示「匯入失敗，資料未變更」

### Requirement: 備份還原一致性

匯出後再匯入同一份檔案，系統 SHALL 還原出完全相同的項目、異動紀錄與設定，推演結果 MUST 與匯出前相同。

#### Scenario: 換裝置還原

- **WHEN** 使用者在裝置 A 匯出備份，並在裝置 B（同一個月份）匯入
- **THEN** 裝置 B 的項目清單、設定與總覽推演結果都與裝置 A 相同
